# ShopSphere — Architecture Decision Record (ADR)
**Student ID:** 30908170106047

## 1. Service Extracted to a Microservice

**Decision:** The **Reviews** functionality was extracted into an independent **Review Service**, with its own codebase (`review-service/`) and its own deployment, connected to the main application through REST endpoints.

**Reason:** Reviews are a self-contained domain — a product ID and a text comment, with no dependency on cart, checkout, or authentication logic. This makes them a low-risk candidate for extraction: the service can be scaled and deployed independently of the main storefront, and a failure or slowdown in the Review Service does not affect the core purchasing flow (browsing, cart, and checkout continue to work even if reviews are temporarily unavailable).

## 2. Workload Moved to Serverless

**Decision:** **Sending a low-stock alert** for a product was moved to a standalone **Vercel Serverless Function** (`low-stock-alert-function`), triggered whenever a product's stock drops to or below a configured threshold.

**Reason:** Checking stock and alerting on it is a short-lived, on-demand side effect that only needs to run occasionally (when stock actually changes), not continuously like the main API. A serverless function fits this naturally: it only executes (and only incurs cost) when triggered, requires no server running idle between checks, and is isolated from the main application, so a failed alert never affects checkout or inventory updates themselves.
